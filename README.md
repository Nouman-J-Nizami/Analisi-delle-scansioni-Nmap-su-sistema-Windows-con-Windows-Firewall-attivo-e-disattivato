# Nmap and Wireshark Analysis of Windows Firewall ON/OFF

## Overview

This project documents a practical cybersecurity laboratory focused on analyzing how Windows Firewall affects network reconnaissance and service discovery operations performed with Nmap.

The assessment compares scan results obtained with Windows Firewall enabled and disabled while observing packet-level behavior through Wireshark.

The project also includes an additional network segmentation experiment where the target system is moved into the same subnet as the attacker to evaluate changes in scan visibility and network communication.

---

## Objectives

- Analyze the impact of Windows Firewall on Nmap scans
- Compare host discovery results with firewall enabled and disabled
- Identify differences in port visibility
- Perform service detection and version enumeration
- Capture and analyze network traffic using Wireshark
- Study TCP and ICMP packet behavior
- Evaluate network reconnaissance techniques in different scenarios

# Phase 1 – Windows Firewall Enabled

## Host Discovery

Host discovery was performed using:

```bash
nmap -sn <target-ip>
```

Results showed that ICMP filtering could prevent proper host identification, causing Nmap to report the target as unreachable despite being online.

---

## SYN Scan

The following scan was executed:

```bash
sudo nmap -sS -Pn <target-ip>
```

Using the -Pn option allowed scanning even when ICMP responses were blocked.

### Analysis

- Open ports were identified
- Several ports appeared filtered
- Firewall rules limited scan visibility
- Wireshark captured TCP SYN traffic and responses

---

## Service Detection

The following command was used:

```bash
sudo nmap -sS -sV -Pn <target-ip>
```

Detected services included:

- Microsoft IIS
- Microsoft RPC
- Terminal Services
- Additional Windows services

Wireshark was used to inspect service detection traffic generated by Nmap.

---

## Full Port Scan

```bash
sudo nmap -p- -Pn <target-ip>
```

This scan evaluated all TCP ports and demonstrated how firewall filtering affects port visibility.

---

# Phase 2 – Windows Firewall Disabled

## Host Discovery

With the firewall disabled:

```bash
nmap -sn <target-ip>
```

The target responded correctly to ICMP Echo Requests and was immediately detected as online.

Wireshark confirmed:

- ICMP Echo Request
- ICMP Echo Reply

---

## SYN Scan

```bash
sudo nmap -sS -Pn <target-ip>
```

Results showed:

- More visible services
- Increased number of accessible ports
- Reduced filtering behavior

Wireshark analysis confirmed successful TCP communication with multiple services.

---

## Service Enumeration

```bash
sudo nmap -sS -sV -Pn <target-ip>
```

Nmap successfully identified:

- Microsoft IIS
- RPC Services
- SMB Services
- Remote Management Services
- Additional Windows network services

---

## Full Port Enumeration

```bash
sudo nmap -p- -Pn <target-ip>
```

The scan revealed significantly more information compared to the firewall-enabled scenario.

# Phase 3 – Same Subnet Analysis

## Objective

The Windows target was moved into the same subnet as the Kali attacker.

The purpose was to analyze:

- Local network visibility
- Scan performance
- Service detection behavior
- Packet exchange characteristics

---

## Observations

### Firewall Disabled

- Host discovery succeeded immediately
- Open ports were easily identified
- Service detection was more efficient

### Firewall Enabled

- Filtering mechanisms remained active
- Some services remained hidden
- Scan visibility was reduced

# Wireshark Traffic Analysis

Throughout the assessment, Wireshark was used to inspect:

- TCP SYN packets
- SYN/ACK responses
- TCP RST packets
- ICMP Echo Requests
- ICMP Echo Replies
- Service detection traffic
- Application-layer communication

This provided visibility into how Nmap interacts with target systems at the packet level.

---

# Key Findings

- Windows Firewall significantly affects reconnaissance results.
- ICMP filtering can prevent standard host discovery.
- SYN scans combined with -Pn can bypass host discovery limitations.
- Service detection reveals valuable information about exposed services.
- Full port scans identify additional attack surface.
- Network segmentation influences scan behavior and visibility.
- Wireshark provides valuable insight into packet-level interactions.
